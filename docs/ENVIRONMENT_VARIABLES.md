# LifeLink — Environment Variables

Every variable, what reads it, and what happens when it is absent.
`.env.example` in the repository root carries placeholders only and is the
file to copy.

## Application

| Variable | Read by | Default | Effect when absent |
|---|---|---|---|
| `LIFELINK_ENV` | Container wiring, seeder guard | `local` | Treated as local: local adapters, seeding permitted |
| `LIFELINK_TABLE_PREFIX` | `repositories/dynamo.py` | `lifelink` | Tables named `lifelink-*` |
| `LIFELINK_DEMO` | Health endpoint | `true` | Demo banner reported as on |
| `LOG_LEVEL` | `appcore/logging.py` | `INFO` | Info-level logging |

`LIFELINK_ENV` accepts `local`, `dev`, `staging` or `prod`. It controls three
things: which adapters the container wires, whether the demo seeder will run,
and the table name prefix in AWS.

## AWS

| Variable | Read by | Default | Effect when absent |
|---|---|---|---|
| `AWS_REGION` | All clients | `ap-southeast-2` | Region defaulted |
| `DYNAMODB_ENDPOINT` | `repositories/dynamo.py` | unset | Real AWS DynamoDB is used |
| `AWS_ACCESS_KEY_ID` | boto3 | — | Local only; a dummy value is set |
| `AWS_SECRET_ACCESS_KEY` | boto3 | — | Local only; a dummy value is set |

> **`DYNAMODB_ENDPOINT` must be absent when running against real AWS.** The
> demo seeder refuses to run if it points at an `amazonaws.com` address, and
> also refuses to run in local mode if it is missing — so a mistake in either
> direction stops rather than writes.

## Identity

| Variable | Read by | Required when |
|---|---|---|
| `COGNITO_USER_POOL_ID` | `appcore/auth.py` | Not local — the container raises without it |
| `COGNITO_CLIENT_ID` | `appcore/auth.py` | Optional; enables explicit client verification |
| `LOCAL_JWT_PUBLIC_KEY` | `appcore/auth.py` | Local only; defaults to `.local-keys/dev_public.pem` |

The local keypair is generated by `python scripts/dev.py keys` into a
gitignored directory. It is for local development only and carries no
authority elsewhere.

## Notifications

| Variable | Read by | Effect when absent |
|---|---|---|
| `SES_SENDER` | `adapters/notifications.py` | Email sending disabled; the SES IAM grant is omitted from the template entirely |

There is deliberately **no SMS variable**. SMS is not implemented: AWS End
User Messaging SMS is a Paid-Plan service and is denied by this account's
service control policy.

## Location

| Variable | Read by | Effect when absent |
|---|---|---|
| `LOCATION_PLACE_INDEX` | `adapters/location.py` | Geocoding raises `ProviderUnavailableError`, surfaced to the client as an unavailable result rather than an error |
| `LOCATION_ROUTE_CALCULATOR` | `adapters/location.py` | Routing returns `NO_ROUTE_CALCULATOR_CONFIGURED`; the straight-line distance is still shown, labelled as such |

## Queues

| Variable | Read by | Effect when absent |
|---|---|---|
| `WORK_QUEUE_URL` | `handlers/workers.py` | The outbox publisher logs an error and reports a batch failure, leaving the row pending |
| `NOTIFICATION_QUEUE_URL` | `handlers/workers.py` | Same |

## Frontend

These are compiled into the browser bundle and are **public**. Never put a
secret in a `VITE_` variable.

| Variable | Read by | Default | Effect when absent |
|---|---|---|---|
| `VITE_API_BASE` | `api/client.js` | `/api` | The Vite dev server proxies `/api` to `localhost:8080` |
| `VITE_MAP_STYLE_URL` | `components/FacilityMap.jsx` | empty | The facility list renders instead of a map, and MapLibre is never downloaded |

## Local server

| Variable | Read by | Default |
|---|---|---|
| `CORS_ORIGINS` | `scripts/local_server.py` | `http://localhost:5173` |

## What is deliberately not an environment variable

| Not a variable | Why |
|---|---|
| Database credentials | DynamoDB uses IAM; there are none |
| Cognito client secret | The browser client uses PKCE and has no secret |
| Map provider key | The browser gets scoped temporary credentials instead |

Three categories of secret that do not exist because of earlier design
choices. The cheapest secret to manage is the one never created.
